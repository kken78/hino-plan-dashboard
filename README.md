# 第6次日野町総合計画 指標と事業費

滋賀県日野町の「第6次日野町総合計画」に関する3つの公開資料から数値を転記し、成果指標・実施計画の事業費・住民意識調査を34分野で並べたページです。個人が作成した試作で、町の公式のものではありません。

外部ビルド不要の SPA（シングルページアプリケーション）で、`index.html` を開くだけで動作します。表現はデジタル庁「ダッシュボードデザインの実践ガイドブック」（2026年3月版）によります。政策の柱の色とグラフの区別の色は、日野町データポータルの共通の決まり（hino-portal DESIGN.md 3.4・3.6）によります。

## 特徴

**1. 3つの情報源を「34分野」で横断**
総合計画の構造（5つの政策の柱 → 10政策 → 34分野）を共通の軸として、以下を1つのダッシュボードに統合しています。

- **基本計画の成果指標（KPI）** … 34分野中30分野・計79指標。基準値 → 中間目標(R7) → 最終目標(R12) の3点を収録
- **実施計画（R7-R9）** … 分野別の概算事業費（3年計・約186億円）と主要事業
- **住民意識調査（R6実施）** … 満足度・協働・幸福度・情報入手・属性など（有効回答1,206件）

**2. 4つのタブ構成**

| タブ | 内容 |
| --- | --- |
| 概要 | 収録している資料の時点、計画期間、KPI数、事業費規模、回収率、幸福度、柱別事業費 |
| 成果指標 | 分野別の成果指標。基準→最終目標の区間で中間目標の位置をバー表示 |
| 実施計画 | 分野別の事業費ランキング（降順）、主要事業 上位12 |
| 住民の声 | 意識調査の設問別グラフ・回答者属性（出典・データ種別を併記） |

**3. 改善の「向き」は基準値と目標値から計算する**
成果指標の改善の向きは、基準値と最終目標（R12）の値から計算し、「増加で改善」「減少で改善」「維持」の文言で示します（hino-portal DESIGN.md 6.1、DESIGN.md ADR-4）。計算した向きが `data/kpi.json` の `direction` と合わない5指標（資源ごみの量、刑法犯認知件数、消費相談件数、消防団団員数、町道改良地区）は、向きを出さず「向きは原典で確かめ中」と示します。`direction` は、原典で確かめてから直します。

**4. モバイル・アクセシビリティ対応**
スマートフォンでは1列レイアウト。キーボードフォーカス表示、`prefers-reduced-motion`（視差効果を減らす設定）に対応。グラフには数値併記と `aria-label` を付与し、元データ（JSON）も `data/` で公開しています。

## ファイル構成

```
index.html        … 本体（構造とスタイル）
README.md         … 本ファイル
og.png            … SNS共有時のサムネイル画像（OGP画像、1200×630px）
assets/
  app.js          … 描画ロジック・タブ制御・達成度計算
  data_bundle.js  … data/ のJSONを結合した埋め込みデータ（index.htmlはこれを読み込む）
  og.svg          … OGP画像の編集元（差し替え用）
data/
  kpi.json        … 全34分野の成果指標
  plan.json       … 実施計画（分野別予算・主要事業）
  survey.json     … 住民意識調査
build.py          … data/*.json から assets/data_bundle.js を再生成するスクリプト
```

データを更新する場合は `data/*.json` を編集し、`python3 build.py` で `assets/data_bundle.js` を再生成してください。

## デジタル庁ガイドブックに沿った設計

- **提示型・全体→部分の構造**：概要タブで全体像（計画期間・指標数・事業費・回収率・幸福度）を示し、各タブで詳細に辿れる導線。フィルターは上部に配置。
- **比較対象を併記**：成果指標は基準値→中間目標(R7)→最終目標(R12)の3点を併記。事業費は降順で大小を比較しやすく配置。
- **誤解を生まない表現**：棒の原点は0。改善の「向き」は、基準値と目標値から計算したものを文言で示し、矢印や色は使わない。バーは「目標の置き方」であり実績の達成状況ではない旨を明記。
- **色のみに依存しない識別**：数値を必ず併記し、凡例をグラフに隣接。バーには `aria-label` を付与。政策の柱の5色は、計画書「体系図」の配色（柱1=`#E72F5C`／柱2=`#ED6D00`／柱3=`#78BC29`／柱4=`#009EB8`／柱5=`#3F51A2`）の色相を保ち、背景との比が 3:1 以上になるまで暗くした色（hino-portal DESIGN.md 3.6。共通の部品の CSS のトークン `--portal-pillar1`〜`5`）です。柱の色は、凡例・分野のカードの左の帯・柱別の事業費の棒にだけ使います。系列が1つだけのグラフ（成果指標の目標の位置、事業費の順位、住民の声の棒など）はポータルの藍（`--portal-ai`）の1色です。区別の色（`--portal-cat1`〜`5`。hino-portal DESIGN.md 3.4）は、同じグラフに系列が2つ以上あるとき（住民の声の構成比のドーナツ）だけ順に当てます。6項目ある世帯構成は、区別の色が5色までなので、横の棒（藍の1色）で示します。
- **メタ情報の明記**：出典・データの定義・いつ時点・更新日・単位・注意をフッターと各グラフに記載。元データ（JSON）へのリンクを掲載。
- **装飾の排除**：グラデーション・ドロップシャドウなどの装飾を撤去し、罫線ベースの簡素な表現に統一。
- **カラーパレット**：背景・文字・リンクはデジタル庁デザインシステムの「Blue」パレット（背景 Standard `#F8F8FB`／Control `#F1F1F4`、テキスト Label `#626264`）。タブの下線・見出しの印・絞り込みの選んだ項目は、ポータルの藍（`--portal-ai`）にそろえ、開いているタブの印だけ朱（`--portal-shu`）にします（hino-portal DESIGN.md 3.5）。グラフの色と政策の柱の色は、共通の部品の CSS のトークンを使います。増減・達成の向きや良し悪しを色で示すことはしません（hino-portal DESIGN.md 3.3）。

## 共通の部品

`index.html` の見出し・分野のナビ・ページの一覧・フッターと、その CSS（`<!-- portal-shared:〈名前〉 start/end -->` で囲んだ部分）は、[hino-portal](https://github.com/kken78/hino-portal) の `shared/` の正本の写しです（DESIGN.md ADR-1）。正本と同じかと文字の大きさ（hino-portal DESIGN.md 5.2、DESIGN.md ADR-3）は `python3 <hino-portal>/shared/check.py --fonts index.html` で、幅 360px と 1024px での文字の実寸と横のはみ出しは `node <hino-portal>/shared/check_mobile.mjs index.html`（Playwright が要る。置き方は hino-portal の shared/README.md）で確かめ、CI（`.github/workflows/check-shared.yml`）でも確かめます。

## ローカルでの確認

`index.html` をブラウザで直接開くだけで動作します（データはJSに埋め込み済みのため簡易サーバ不要）。

## 今後の拡張余地

- **KPIに「現在地（実績値）」を重ねる**：現在は基準値→目標値のみ。各指標の最新実績が公表されれば、実績に基づく達成状況を表示できます。
- **住民意識調査の「定着度×優先度」マトリクス**：34施策を4タイプに分類する散布図は、概要版PDFでは画像化されており数値が読み取れませんでした。元の詳細報告書（数表）が入手できれば、この散布図を足せます。
- **実施計画の経年比較**：過去年度（R3-R5〜R6-R8）のPDFが公開済みのため、事業の追加・変更の経年比較が可能です。

## 注意事項

- 本リポジトリのデータは公開PDFから独自に抽出して作成したものです。読み取り誤差や変換ミスを含む可能性があるため、正確な数値が必要な場合は必ず日野町公式の元資料（PDF）をご確認ください。
- 一部分野は中間目標の年次がR7と揃っていない（R5・R6表記）、基準値の年次が分野によりR1/R2見込み/H27〜H28と異なる、などの点があります。データには年次を併記しています。
- このページは日野町の公式のものではなく、個人が作成した試作です。

## 町のページの巡回

毎月1日の朝（JST）に、GitHub Actions（`.github/workflows/watch.yml`）が町の「第6次日野町総合計画」「実施計画」「基本計画の中間見直し」の3ページを巡回し、見つけたものを Issue にします。道具は `tools/watch.py`（標準ライブラリだけ。取得は1秒に1件以内）、見るページは `data/watch.json`、知っている資料とページの更新日は `data/watch.tsv` です。

| 見つけるもの | 確かめ方 |
|---|---|
| 新しい資料 | 見るページに、`data/watch.tsv` に無い PDF のリンクがある |
| 資料が取れない | `data/watch.tsv` で status が「使用」の PDF（総合計画の本編7本と実施計画（令和7〜9年度））が、ページからリンクされなくなったか、404 などで取れない |
| ページの更新 | ページの「更新日」が `data/watch.tsv` の updated と違う |

巡回は見つけるだけで、`data/` のデータと画面は変えません。Issue の本文の「次にやること」に従って転記し、`data/watch.tsv` に行を足すか updated を直します（直さないと次の月にまた Issue ができます）。巡回そのものに失敗したときは、ワークフローが失敗して「巡回に失敗した」Issue ができます。同じ内容の Issue が開いていれば作りません。手元では `python3 tools/watch.py` で確かめられます。定期実行は60日間コミットが無いと止まるため、`.github/workflows/keepalive.yml` が毎月1日に有効化し直します。
